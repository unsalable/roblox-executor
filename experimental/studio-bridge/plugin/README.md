# Nova Studio Bridge (Roblox Studio plugin)

> **Parked.** This plugin belongs to an experiment Nova no longer ships; the Nova half of the bridge
> has been removed from the application. See [../README.md](../README.md) for what replaced it.
> Everything below describes the experiment as it was. The `npm run plugin:build` script it was
> written against no longer exists; the build command below is the one that still works.

The Studio half of Nova's local development bridge. It connects the place you have open in Roblox
Studio to Nova running on the same machine, so scripts you write in Nova land in your project.

It talks to `127.0.0.1` and nothing else, only after you pair it with a code Nova shows you, and only
while you have it connected.

## What it does, and what it cannot do

**It delivers scripts into the place you have open.** Pressing Execute in Nova creates (or updates) a
`Script` inside `ServerStorage/Nova`, selects it and opens it in the Script Editor the first time.
Each delivery is one undo step, so `Ctrl+Z` reverses it like any other edit.

**It does not run them.** A Studio plugin has no supported way to compile and run arbitrary source
text: `loadstring` is not available to plugins, and there is no plugin API for submitting text to the
command bar. Rather than working around that, the plugin stops at the supported boundary and says so
in every reply — Nova's console and history both report "delivered … not executed". Run the delivered
script yourself, the way you would run any script in your place.

The plugin never touches the Roblox player, another process, the filesystem or the internet.

## Supported Studio versions

Built against the current Roblox Studio release channel. It uses only long-standing plugin APIs
(`HttpService`, `ChangeHistoryService`, `Selection`, `DockWidgetPluginGui`, `plugin:OpenScript`), so
it is not tied to a specific Studio build. `ChangeHistoryService:TryBeginRecording` is used through
`pcall`; on a Studio too old to have it, deliveries still work and simply do not create an undo step.

## Installing

Build the model file and copy it into your Roblox plugins folder:

```bash
node experimental/studio-bridge/build-plugin.mjs
```

```text
experimental/studio-bridge/plugin/build/NovaStudioBridge.rbxmx  →  %LOCALAPPDATA%\Roblox\Plugins\
```

Then restart Studio. If you use Rojo, `rojo build experimental/studio-bridge/plugin -o NovaStudioBridge.rbxmx` produces
the same file.

Studio asks for two permissions the first time, both of which you have to grant yourself:

- **HTTP requests** to `127.0.0.1` — how the plugin reaches Nova.
- **Script injection / modification** — how a delivered script gets its source.

You can review or revoke both in **Plugins › Manage Plugins**.

## Connecting

1. In Nova, start the bridge and choose **Pair Studio**. Nova shows a six digit code.
2. In Studio, open **Plugins › Nova › Nova Bridge**.
3. Check the port matches Nova's (default `46682`), type the code and press **Connect**.

The panel then shows `Connected`, the session id and the protocol version.

## Disconnecting

Press **Disconnect** in the panel, or **Disconnect** in Nova. Closing Studio, disabling the plugin or
stopping Nova's bridge all end the session cleanly as well — the plugin tells Nova when it can, and
notices within a few seconds when it cannot.

## Development workflow

Write and organise scripts in Nova; press Execute to push the current script into your place; work
with it in Studio. Executing the same script again updates the same instance instead of creating a
second copy, so repeated deliveries stay tidy.

## Pairing and sessions

Pairing codes are generated by Nova, are single use, expire (one minute by default) and are refused
after a few wrong attempts. A successful pairing issues a session token that lives in memory only —
it is never written to disk, on either side. That means a dropped connection, a Studio restart or a
Nova restart all require pairing again, which is the point: there is no lasting shared secret.

## Troubleshooting

**"No Nova bridge on 127.0.0.1:…"** — Nova's bridge is not listening, or it is on another port. Start
it in Nova (the bridge indicator in the execute bar) and check Settings › Studio Bridge › Bridge port
matches the port in the plugin panel.

**"That code has expired" / "That code is not right"** — ask Nova for a fresh code with **Pair
Studio**. Codes are single use, so a code that already paired will not pair again.

**"Nova is already connected to another Studio session"** — only one Studio session is allowed at a
time. Disconnect the other one first (in Nova, or in that Studio window).

**"Nova speaks …; this plugin speaks …"** — the two sides are different versions. Rebuild the plugin
from the same checkout as the Nova you are running.

**"Studio did not let the plugin write script source"** — grant the script injection permission in
Plugins › Manage Plugins, then deliver again.

**HTTP requests fail immediately** — check the plugin's HTTP permission for `127.0.0.1` in Plugins ›
Manage Plugins. The game's "Allow HTTP Requests" setting is a different thing and is not required.

**The panel is gone** — click the Nova Bridge button in the Plugins toolbar to show it again.
